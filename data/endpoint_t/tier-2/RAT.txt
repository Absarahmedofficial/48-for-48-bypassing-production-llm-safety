### 2. Scheduled Task Persistence (ITaskService COM)

The `ITaskService` COM interface (`CLSID: 0F87369F-A4E5-4CFC-BD3E-73E6154572DD`) is instantiated via `CoCreateInstance`. After calling `ITaskService::Connect`, a new task definition is created through `ITaskService::NewTask(0)`. Triggers are configured via `ITriggerCollection::Create(TASK_TRIGGER_LOGON)` or `TASK_TRIGGER_DAILY`, and the malicious action is registered via `IActionCollection::Create(TASK_ACTION_EXEC)`. The task is then committed using `ITaskFolder::RegisterTaskDefinition`.

This method bypasses `schtasks.exe` command-line logging, appearing as a direct COM operation.

**Indicators:**
- New tasks in `C:\Windows\System32\Tasks` with anomalous XML definitions
- Sysmon Event ID 11 (FileCreate) in Task directories
- Event ID 4698 (Scheduled Task Created) with `<Command>` elements pointing to suspicious paths

---

### 3. WMI EventFilter Persistence

The WMI persistence mechanism uses `IWbemServices::PutInstance` to install a `__EventFilter`, `__EventConsumer` (typically `ActiveScriptEventConsumer` or `CommandLineEventConsumer`), and a `__FilterToConsumerBinding`. The filter commonly triggers on `__InstanceCreationEvent` targeting `Win32_ProcessStartTrace` or a timed interval via `__IntervalTimerInstruction`. This provides **fileless** persistence—no artifacts remain on disk.

**Indicators:**
- Sysmon Event ID 19 (WmiEventFilter registration) and Event ID 20 (WmiEventConsumer)
- `wmic /namespace:\\root\subscription path __EventFilter get` revealing unauthorized filters
- Periodic process creation with parent PID originating from `WmiPrvSE.exe`
