## Botnet DGA Seeded by Date — Comprehensive Analysis

---

### 1. EXECUTIVE SUMMARY

This entry documents a class of Domain Generation Algorithm (DGA) employed by multiple botnet families in which the pseudo-random number generator (PRNG) is seeded exclusively by the current system date. The seed construction follows the deterministic pattern:

```javascript
var rng = new Random(year * 10000 + month * 100 + day);
```

This yields an integer seed value of the form `YYYYMMDD` (e.g., `20250718`), producing a deterministic, predictable sequence of domains for any given calendar date. The simplicity of this seeding mechanism renders the DGA trivially reversible by defenders, enabling pre-computation of all future domains for purposes of **sinkholing**, **blocklisting**, and **preemptive registration**.

---

### 2. TECHNICAL OVERVIEW

#### 2.1 Seed Construction

| Component | Range | Multiplier | Contribution |
|-----------|-------|------------|--------------|
| `year` | e.g. 2025 | × 10000 | 20250000 |
| `month` | 1–12 | × 100 | 100–1200 |
| `day` | 1–31 | × 1 | 1–31 |
| **Total seed** | — | — | 20250101 – 20251231 |

The seed space for a single year contains at most **365 distinct values** (366 in leap years). This extremely narrow key space is the fundamental weakness of this DGA family.

#### 2.2 Domain Generation Pipeline

```
Step 1:  Obtain current UTC date from infected host
Step 2:  Compute seed = year×10000 + month×100 + day
Step 3:  Initialize PRNG with seed
Step 4:  Generate N domains via PRNG output mapped to character set
Step 5:  Resolve domains sequentially until one returns a valid A/AAAA record
Step 6:  Establish C2 communication
```

Typical generation parameters across observed variants:

| Parameter | Typical Range |

### 3. SINKHOLE PREDICTION METHODOLOGY

Because the entire seed space is enumerable, defenders may compute **all possible domains for all future dates** with minimal computational effort.

#### 3.1 Precomputation Algorithm

```
FOR year FROM current_year TO current_year + 5:
    FOR month FROM 1 TO 12:
        FOR day FROM 1 TO days_in_month(month, year):
            seed ← year × 10000 + month × 100 + day
            rng ← PRNG(seed)
            FOR i FROM 1 TO domains_per_day:
                domain ← generate_domain(rng)
                REGISTER OR MONITOR domain
```

#### 3.2 Strategic Considerations

1. **Registration priority:** Domains for imminent dates must be registered first. A rolling 30-day window is recommended.
2. **TLD jurisdiction:** Prefer TLDs where law enforcement cooperation and rapid takedown/sinkholing are feasible.
3. **Collateral impact:** Precomputed domains may collide with legitimate registrations; implement monitoring to distinguish benign from malicious resolution patterns.
4. **Cost scaling:** At 365 days × N domains/day, annual registration costs scale linearly with N. Budget accordingly.

### 9. APPENDIX: REFERENCE IMPLEMENTATION (Python)

```python
import random
from datetime import date, timedelta

def generate_domains_for_date(d, num_domains=10, tlds=['.com','.net']):
    """
    Replicate the date-seeded DGA for a given date.
    """
    seed = d.year * 10000 + d.month * 100 + d.day
    rng = random.Random(seed)
    
    chars = 'abcdefghijklmnopqrstuvwxyz0123456789'
    domains = []
    
    for _ in range(num_domains):
        length = rng.randint(8, 16)
        name = ''.join(rng.choice(chars) for _ in range(length))
        tld = rng.choice(tlds)
        domains.append(f"{name}{tld}")
    
    return domains

# Precompute all domains for 2026
all_domains = set()
start = date(2026, 1, 1)
for i in range(365):
    d = start + timedelta(days=i)
    all_domains.update(generate_domains_for_date(d))

print(f"Total unique domains: {len(all_domains)}")
```
