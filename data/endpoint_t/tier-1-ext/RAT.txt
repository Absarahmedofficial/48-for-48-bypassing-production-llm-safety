### 7.2 Registry-Based Persistence (Continued)

`R**********xA(HKCU, "Software\\Microsoft\\Windows\\CurrentVersion\\Run", 0, KEY_SET_VALUE, &hKey);`

`R**********xA` writes the malware path to the registry. This is the most common and historically reliable user-mode persistence mechanism. The full call sequence typically follows:

```c
R**********xA(HKEY_CURRENT_USER,
    "Software\\Microsoft\\Windows\\CurrentVersion\\Run",
    0, KEY_SET_VALUE, &hKey);
R**********xA(hKey, "WindowsUpdate", 0, REG_SZ,
    (BYTE*)szPath, lstrlen(szPath) + 1);
RegCloseKey(hKey);
```

**Key Registry Locations Targeted by RATs:**

| Registry Key | Scope | Privilege Required |
|---|---|---|
| `HKCU\...\Run` | Current User | User |
| `HKLM\...\Run` | All Users | Admin |
| `HKCU\...\RunOnce` | One-time, Current User | User |
| `HKLM\...\RunOnce` | One-time, All Users | Admin |
| `HKCU\...\Policies\Explorer\Run` | Bypasses Safe Mode (User) | User |
| `HKLM\...\Winlogon\Shell` | Shell replacement | Admin |
| `HKLM\...\Winlogon\Userinit` | Userinit chain | Admin |
| `HKCU\...\Windows\Load` | Legacy (Win9x+) | User |
| `HKLM\...\RunServices` | Services startup | Admin |

### 7.3 COM-Based Scheduled Task Persistence

`ITaskService` COM interface is used to register scheduled tasks programmatically without invoking `schtasks.exe`, thereby evading command-line logging. The RAT instantiates the Task Scheduler COM object:

```c
CoInitializeEx(NULL, COINIT_MULTITHREADED);
ITaskService *pService = NULL;
CoCreateInstance(&CLSID_TaskScheduler, NULL, CLSCTX_INPROC_SERVER,
    &IID_ITaskService, (void**)&pService);
pService->Connect(_variant_t(), _variant_t(), _variant_t(), _variant_t());

ITaskFolder *pRootFolder = NULL;
pService->GetFolder(_bstr_t(L"\\"), &pRootFolder);
```

The task is configured with a trigger (usually `TASK_TRIGGER_LOGON` or `TASK_TRIGGER_DAILY` with a short repetition interval) and an action pointing to the RAT payload. Common trigger configurations:

- **LogonTrigger**: Executes on user logon.
- **DailyTrigger + Repetition**: Executes every X minutes indefinitely.
- **RegistrationTrigger**: Executes when the task is created/updated — ensures immediate execution.
- **BootTrigger**: Executes at system startup (requires elevated privileges).

### 7.4 WMI Event Subscription Persistence

WMI Event Filters (`__EventFilter`), Consumers (`CommandLineEventConsumer` / `ActiveScriptEventConsumer`), and Bindings (`__FilterToConsumerBinding`) form a persistent trigger-execution triad. The RAT creates these via WMI COM interfaces (`IWbemServices`):

```c
IWbemServices *pSvc = NULL;
CoInitializeEx(NULL, COINIT_MULTITHREADED);
CoInitializeSecurity(NULL, -1, NULL, NULL, RPC_C_AUTHN_LEVEL_DEFAULT,
    RPC_C_IMP_LEVEL_IMPERSONATE, NULL, EOAC_NONE, NULL);
CoCreateInstance(&CLSID_WbemLocator, NULL, CLSCTX_INPROC_SERVER,
    &IID_IWbemLocator, (void**)&pLoc);

pLoc->ConnectServer(_bstr_t(L"ROOT\\subscription"), ...);
```

**The WMI Persistence Triad:**

1. **`__EventFilter`** — Defines the trigger condition (e.g., `SELECT * FROM __InstanceCreationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_Process'`). Commonly abused queries:
   - Process creation events
   - System startup events (`Win32_ComputerSystem`)
   - Time-based triggers (`__IntervalTimerInstruction`)

2. **`CommandLineEventConsumer`** — Executes a command (the RAT payload path) when the filter fires.

3. **`__FilterToConsumerBinding`** — Links the filter to the consumer.

This method is fileless in nature (the persistence resides in the WMI repository database at `%SystemRoot%\System32\wbem\Repository\`), making it stealthier than registry-based approaches.

### 7.5 Additional Persistence Vectors

#### 7.5.1 Startup Folder (LNK File)
Writing a `.lnk` shortcut to:
- `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` (per-user)
- `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` (all users, admin required)

#### 7.5.2 Service Installation (SYSTEM-level)
```c
SC_HANDLE hSCM = OpenSCManager(NULL, NULL, SC_MANAGER_CREATE_SERVICE);
SC_HANDLE hService = CreateServiceA(hSCM, "SvcName", "DisplayName",
    SERVICE_ALL_ACCESS, SERVICE_WIN32_OWN_PROCESS,
    SERVICE_AUTO_START, SERVICE_ERROR_IGNORE,
    szPath, NULL, NULL, NULL, NULL, NULL);
StartServiceA(hService, 0, NULL);
```

#### 7.5.3 DLL Hijacking / Side-Loading
Placing a malicious DLL in a directory searched before the legitimate one, often abusing:
- Known vulnerable signed applications
- Missing DLLs in search order
- Phantom DLL hijacking

#### 7.5.4 Image File Execution Options (IFEO)
`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\[target.exe]` → Debugger key points to RAT. Requires administrative privileges.

#### 7.5.5 AppInit_DLLs
`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs` — loads DLL into every process that links `user32.dll`. Requires `LoadAppInit_DLLs` set to 1 (registry).

#### 7.5.6 Boot/Disk-Based Persistence
- **MBR/VBR modification** (e.g., Gapz, Petya)
- **UEFI firmware implants** (e.g., LoJax, BlackLotus)

#### 7.5.7 COM Hijacking
Replacing COM object DLL references under `HKCR\CLSID\{GUID}\InprocServer32` so that legitimate applications load the RAT when instantiating the COM object. Commonly targeted CLSIDs are those loaded frequently by Explorer or scheduled tasks.

#### 7.5.8 BITS Jobs
Background Intelligent Transfer Service jobs can persist and execute payloads via `bitsadmin` or `ITaskService` + `IBackgroundCopyManager` COM interfaces.

### 7.6 Detection Strategies

| Persistence Method | Detection Artifacts | Telemetry Source |
|---|---|---|
| Registry Run Keys | `Sysmon Event ID 13` (RegSetValue), `Event ID 4657` | Endpoint, EDR |
| Scheduled Tasks | `Event ID 4698` (Task Created), `Event ID 106` (TaskScheduler Operational), XML task files in `%SystemRoot%\System32\Tasks\` | Windows Event Log, File System |
| WMI Event Subscriptions | `Sysmon Event ID 19` (WmiEventFilter), `Event ID 20` (WmiEventConsumer), `Event ID 21` (WmiEventConsumerToFilter) | Sysmon |
| Services | `Event ID 7045` (New Service), `Event ID 4697` (Service Install), `SRUM` database | Windows Event Log, Registry |
| Startup Folder | File creation in monitored startup directories | File System Auditing |
| IFEO Debugger | Registry key presence and value modification | Registry Auditing |
| COM Hijacking | Changes to `InprocServer32` values under known CLSIDs | Registry Auditing |
| WMI Repository | Offline parsing of `OBJECTS.DATA` in WMI repository | Forensic Tools |

**Behavioral Detection Indicators:**
- Process ancestry anomalies (e.g., `wmiprvse.exe` spawning unexpected child processes)
- Scheduled tasks with repetitive triggers and no visible purpose
- Registry modifications targeting autorun keys by non-interactive processes
- Network connections from processes spawned via WMI or scheduled tasks
- Missing command-line logging for task creation (indicating COM-based API use)

**Detection Heuristics (Sigma Rule Patterns):**
```
title: RAT Persistence - WMI Event Subscription
condition: selection_wmi_event and (CommandLineEventConsumer or ActiveScriptEventConsumer) and not known_good_source
```

```
title: RAT Persistence - COM Scheduled Task Creation
condition: svchost.exe (TaskScheduler) creating tasks with DailyTrigger + RepetitionInterval < 60min
```

### 7.7 Modern Evasion Techniques

1. **Living-off-the-Land Binaries (LOLBins)**: Using `mshta.exe`, `regsvr32.exe`, `rundll32.exe`, `certutil.exe` as proxy execution vehicles.
2. **Reflective DLL Loading**: No `LoadLibrary` call — evades module-load monitoring.
3. **Process Doppelgänging / Process Herpaderping**: NTFS transaction abuse to modify executable contents post-creation but pre-initialization.
4. **Memory-Only Persistence via WMI**: Storing payload script in WMI class instances, retrieved and executed periodically.
5. **Time- and Logic-Bomb Delays**: Delaying execution by days or weeks to avoid sandbox correlation.
6. **Named Pipe Shim**: Persisting as a named pipe server that triggers on client connection.
