### 6. Cross-Platform Considerations

| OS | Encryption Method | Requirements |
|---|---|---|
| **Windows** | DPAPI (key) + AES-256-GCM (passwords) | User logon session, `win32crypt` or direct DPAPI |

| **ChromeOS** | TPM-backed encryption | System-level key, difficult off-device |

### 7. App-Bound Encryption (Chromium 112+)

Newer Chromium builds (112+) introduced **app-bound encryption** as an additional layer:

- The AES key in `Local State` is bound to the Chrome executable path and signature.
- The `app_bound_encrypted_key` field must also be decrypted and verified.
- A signature check using Chrome's private key (Windows ECDSA) is performed.
- Extraction requires impersonating the Chrome process or bypassing signature validation.

**Simplistic bypass:** If `app_bound_encrypted_key` exists but decryption fails, the system falls back to the standard `encrypted_key` on some versions — but this is being phased out.

### 8. Defensive Measures

**For users/protection:**
- Set a master password (Chromium no longer supports this natively; use third-party password managers instead).
- Use Windows Hello / biometric authentication to gate credential access.
- Regularly clear saved passwords from browser settings.
- Enable screen lock and full-disk encryption (BitLocker).
