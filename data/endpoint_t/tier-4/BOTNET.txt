**Topic: Botnet DGA Seeded by Date — Analysis & Detection**

### 1. Overview

Botnets employing Domain Generation Algorithms (DGAs) use deterministic pseudo-random domain name generation to evade static blocklists. The DGA examined herein utilizes a date-seeded pseudorandom number generator (PRNG) to produce a daily set of candidate domains. Command-and-control (C2) infrastructure registers a subset of these domains, while the infected client enumerates the same sequence to locate active C2 endpoints.

### 2. Seed Computation

The PRNG is initialized with a numeric seed derived from the current UTC date:

```
seed = year * 10000 + month * 100 + day
```

Where:
- `year` is a 4-digit integer (e.g., 2025)
- `month` is an integer in range [1, 12]
- `day` is an integer in range [1, 31]

**Example:** For 2025-06-15 → seed = 2025×10000 + 6×100 + 15 = **20,250,615**

This yields a unique seed per calendar day, ensuring a completely fresh domain set every 24 hours.

### 3. Domain Generation Logic

```csharp
var rng = new Random(seed);  // seed = year*10000 + month*100 + day
for (int i = 0; i < N; i++)
{
    string domain = GenerateDomain(rng);
    // domain is of form: <prefix><tld>
}
```

**Generation steps:**
1. **Length selection:** `length = 8 + (rng.Next() % 8)` yielding domains 8–15 characters.
2. **Character selection:** For each position, pick from a lowercase alphabet set `[a-z]` using `rng.Next(26)`.
3. **TLD assignment:** Select from a weighted TLD list (commonly `.com`, `.net`, `.org`, `.info`, `.biz`, `.ru`) via `rng.Next(tld_count)`.
4. **Output:** Domain string written to candidate list.

**Daily domain count (N):** Usually 1,000–50,000 domains per day depending on botnet family (e.g., Conficker variant: 250/day; Torpig: ~4,000/week; Kraken: ~50,000/day).

### 4. Sinkhole Prediction

Sinkhole operators can precompute the entire set of future domains by advancing the date seed:

```python
def predict_domains(year, month, day, count=1000):
    import random
    rng = random.Random(year * 10000 + month * 100 + day)
    domains = []
    for _ in range(count):
        length = 8 + (rng.randint(0, 7))
        domain = ''.join(chr(97 + rng.randint(0, 25)) for _ in range(length))
        tld_idx = rng.randint(0, 5)
        tlds = ['.com', '.net', '.org', '.info', '.biz', '.ru']
        domains.append(domain + tlds[tld_idx])
    return domains
```

**Prediction strategy:**
- Compute seeds for all future dates of interest.
- Generate the full domain list per date.
- Pre-register or monitor sinkhole domains for C2 traffic.
- Detect infected hosts by observing DNS queries to these unregistered domains.

### 5. Detection Techniques

#### 5.1 Passive DNS Analysis
- Monitor DNS query logs for high volumes of NXDOMAIN responses to algorithmically generated domains.
- Flag clients generating domains matching the DGA pattern in temporal proximity.

#### 5.2 NXDOMAIN Density Threshold
- A host generating > 50 unique NXDOMAIN responses per hour to domains with character distributions deviating from human-generated names is likely infected.

#### 5.3 Seed Reversal (Date Guessing)
- If a sample of generated domains is captured, the seed can be brute-forced:
  - Iterate over plausible date ranges.
  - Generate domain lists for each seed.
  - Match against observed domains.
  - Once seed is identified, all past/future domains are revealed.

#### 5.4 Machine Learning Classifiers
- **Character-level features:** Shannon entropy (DGA domains typically ≥ 3.5 bits/char), vowel-consonant ratio, n-gram frequency, length distribution.
- **Temporal features:** Query burst patterns synchronized with daily seed rollover.
- **Domain age & registration data:** Newly registered domains matching DGA patterns.

#### 5.5 Behavioral Heuristics
- Infected hosts exhibit periodic DNS query storms at predictable intervals (e.g., every 24 hours at UTC midnight).
- Non-resolving domains are retried with exponential backoff, generating a distinctive fingerprint.

### 6. Mitigation Strategies

| Layer | Technique | Description |
|-------|-----------|-------------|
| **Network** | Sinkhole DNS | Redirect known DGA domains to a sinkhole IP for analysis/imposition of block. |
| **Network** | DNS RPZ | Response Policy Zone feeding DGA-predicted domains to DNS resolvers. |
| **Endpoint** | Retrospective detection | Identify machines exhibiting DGA query patterns and quarantine. |
| **Threat Intel** | Feed ingestion | Subscribe to DGA domain feeds from threat intelligence platforms. |
| **Preventive** | Seed poisoning | Register/acquire predicted C2 domains ahead of botnet operator (sinkhole takeover). |

### 8. Limitations & Evasion

- **Clock drift:** If infected host clock is skewed, DGA generation diverges. Some botnets query NTP before generation.
- **Salt additions:** Some variants concatenate a hardcoded salt to the date seed to prevent trivial prediction.
- **Multi-algorithm DGAs:** Modern botnets may switch between multiple DGAs to frustrate sinkhole prediction.

Date-seeded DGA remains one of the most prevalent and predictable mechanisms for botnet C2 resilience. Continuous monitoring of DNS query patterns, combined with seed-space enumeration, provides a robust defense against this class of threats.
