### Botnet DGA (Domain Generation Algorithm): Date-Seeded Deterministic Variants

**Classification:** Malware C2 Failover / Domain Flux | **First Catalogued:** ~2008–2014 (multiple strains)  
**Primary Seed Formula:** `var rng = new Random(year * 10000 + month * 100 + day);`

---

## 1. OVERVIEW

A **date-seeded Domain Generation Algorithm (DGA)** is a deterministic mechanism embedded in botnet malware that computes pseudorandom domain names from the current system date. By seeding a PRNG with a function of the date — most commonly `year × 10000 + month × 100 + day` (producing an integer seed, e.g., `20240115` for 15 January 2024) — the bot produces the same candidate-domain list on every infected host worldwide, without any network coordination, on a given calendar day. This technique, a subset of **domain flux**, enables the malware to re-establish contact with its command and control (C2) infrastructure even after prior domains are seized or blacklisted.

---

## 2. TECHNICAL MECHANISM

### 2.1 Generalized Algorithm

```
SEED ← YEAR × 10000 + MONTH × 100 + DAY
PRNG ← Random(SEED)

FOR i ← 1 TO N_DOMAINS_PER_DAY:
    length ← PRNG.Next(MIN_LEN, MAX_LEN)
    domain ← ""
    FOR j ← 1 TO length:
        domain ← domain + CHAR(PRNG.Next('a', 'z'))
    END FOR
    domain ← domain + "." + TLD_LIST[PRNG.Next(0, TLD_COUNT)]
    OUTPUT domain
END FOR
```

### 2.2 Why Date-Seeding?

| Property | Advantage to Attacker |
|---|---|
| **No key distribution needed** | Every infected host computes the same domains using only the system clock |
| **Difficult to pre-blacklist** | Domains change every 24 hours; defenders must compute them reactively |
| **Sinkhole-able by defenders** | If the algorithm is reverse-engineered, *defenders* can also pre-register the day's domains |
| **Fallback resilience** | Works even when P2P mesh, hardcoded IPs, and prior C2 domains all fail |

## 4. SINKHOLE PREDICTION METHODOLOGY

### 4.1 Reverse-Engineering the DGA

1. **Static Analysis:** Extract the compiled algorithm from the malware binary (e.g., via IDA Pro, Ghidra, or x64dbg).
2. **Dynamic Analysis:** Run the sample in a sandbox with a *known date* and capture DNS queries to validate the domain list.
3. **Seed Confirmation:** Verify that changing the system date produces the *identical* domain set predicted by `Random(year*10000 + month*100 + day)`.

### 4.2 Proactive Registration Pipeline

```
Today ← GET_CURRENT_DATE()
Tomorrow ← Today + 1 Day
PRNG ← Random(Tomorrow.Year * 10000 + Tomorrow.Month * 100 + Tomorrow.Day)
DOMAINS ← GenerateAll(PRNG, N_DOMAINS)

FOR EACH domain IN DOMAINS:
    IF domain NOT registered:
        REGISTER(domain)
        CONFIGURE_DNS_SINKHOLE(domain → SINKHOLE_IP)
    END IF
END FOR
```

### 4.3 Operational Considerations

| Challenge | Mitigation |
|---|---|
| **Seed drift** | Monitor multiple seed offsets (e.g., seed, seed±1, seed±2) |
| **TLD expansion** | Watch for malware updates that add new TLDs |
| **Domain collision** | Some domains may already be legitimately registered — legal/ethical clearance required |
| **Scale** | For DGAs producing thousands of domains/day (e.g., GOZ = 1,000/day), automated registration infrastructure is essential |

## 5. DETECTION SIGNATURES

### 5.1 Network-Based Detection (NIDS / DNS)

```
ALERT on:
  DNS query to domain matching pattern ^[a-z]{8,24}\.(com|net|org|info|biz)$
```

### 5.2 Host-Based Detection (Endpoint)

| Indicator | Method |
|---|---|
| **DNS API call spikes** | Monitor `DnsQuery_*` / `getaddrinfo` call frequency |
| **NXDOMAIN burst** | Windows Event Log: DNS Client Events 1014 (name resolution timeout) in rapid succession |
| **Process behavior** | A process generating random-looking DNS queries with no user-initiated browsing |
| **YARA Rule (illustrative)** | `$dga_seed = { 69 C0 10 27 00 00 ... }` — targeting the `year*10000` multiplication constant `0x2710` |

### 5.3 Machine Learning Approaches

- **Entropy scoring** of queried domain names (random domains have near-maximum per-character entropy).
- **NXDOMAIN response ratio** — healthy hosts have >95% successful resolutions; DGA-infected hosts may show XX-XX% NXDOMAIN.
- **Temporal clustering** — DGA queries often concentrate in the first minutes after midnight UTC.

## 7. VARIANTS AND EVOLUTION

Over time, malware authors have introduced refinements to the basic date-seed pattern:

| Variant | Description |
|---|---|
| **Static + Date hybrid seed** | `seed = HARDCODED_KEY XOR (year*10000 + month*100 + day)` — makes prediction harder without the key |
| **Rolling window** | Domains generated for *today ± N days*, giving the bot a wider window to find C2 |
| **Hour-granularity** | `seed = year*10000 + month*100 + day*100 + hour` — domains rotate every hour |
| **TLD cycling** | Different TLD sets used on different days (e.g., odd days = `.com/.net`, even days = `.org/.info`) |
| **Dictionary-based DGA** | Instead of random characters, seed selects from a hardcoded English-word dictionary (e.g., `bluesky.com`, `redtree.net`) — much harder to distinguish from legitimate traffic |
